Git and GitHub: A Beginner's Guide for Students

By Omkar Solat | 10 August 2026

Introduction

In my first semester I saved every project in a folder called final-project-final-2 . By the end of the semester I had twelve folders with almost the same name and no idea which one actually worked. That is the day I understood why version control exists.

Git is the tool that keeps a history of your work, and GitHub is the website that keeps a copy of it online. Together they are the first thing every student should learn after HTML and CSS.

What Is Version Control?

Version control is a system that records every change you make to your files. Instead of copying a whole folder and renaming it, you save small "snapshots" of your project with a short note. You can jump back to any snapshot at any time.

Git runs on your own computer. GitHub is an online place where you upload those snapshots, so they are safe even if your laptop stops working.

Why Should Students Learn Git?

  • You can go back to an older version when a new change breaks your project.
  • Your work is safe online, so a stolen or broken laptop does not end your semester.
  • Teachers and teammates can see exactly what you changed and when.
  • Almost every company expects it, even for internships.
  • Group projects stop being a mess of WhatsApp file sharing.

Setting Up Git in Five Steps

  1. Download Git from git-scm.com and install it with the default options.
  2. Open the terminal (Git Bash on Windows) and tell Git your name and email address.
  3. Go into your project folder and run git init to start tracking it.
  4. Select your files with git add . and save them with git commit -m "first commit" .
  5. Create a repository on GitHub and connect it to your folder with git remote add origin .

The Commands I Use Every Day

  • git status - shows which files have changed.
  • git add . - selects all the changes for the next snapshot.
  • git commit -m "message" - saves the snapshot with a note.
  • git push - uploads your snapshots to GitHub.
  • git pull - brings the newest changes down from GitHub.

Branches In Simple Words

A branch is a separate copy of your project where you can try something new without touching the working version. The main branch stays safe while you experiment. When the experiment works, you merge the branch back into main.

For a small college project you can do everything on the main branch. It is still useful to know the idea, because in a real team everyone works on their own branch.

Mistakes I Made, So You Do Not Have To

  • Making one huge commit at the end of the day instead of saving small changes.
  • Writing commit messages like "update" or "done". Write what actually changed.
  • Uploading passwords or database keys along with the code.
  • Forgetting to pull before pushing when working with a partner.

Conclusion

Git feels confusing for the first two days because it has a lot of new words. After that it becomes the most useful tool in your project folder. Start with add , commit and push , and learn the rest when you actually need it.
